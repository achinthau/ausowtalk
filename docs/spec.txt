Auso Call Hub — WebRTC Phone Requirements
1. Core architecture

For the first production version, I would use SIP.js or a similar modern SIP/WebRTC library rather than building SIP signaling from scratch. SIP.js specifically supports Asterisk and browser WebRTC, including hold and transfers. 




2. Automatic registration
This is one of your most important requirements.
Agent login
Agent logs into Auso Call Hub
↓
Laravel authenticates agent
↓
Laravel gets SIP credentials
↓
WebRTC Phone initializes
↓
Connect WSS
↓
SIP REGISTER
↓
Asterisk
↓
Registered
The agent should not manually enter SIP username/password.
For example, Laravel could provide:
{
    "extension": "2002",
    "sip_domain": "pbx.ausoworld.com",
    "ws_url": "wss://pbx.ausoworld.com:8089/ws",
    "password": "clear text password"
}
Then:
phone.connect();
phone.register();
SIP.js supports connecting and registering programmatically. 

Security recommendation
Don't expose the permanent SIP password in the HTML page.
Use a Laravel-generated short-lived credential/token and have a backend service provision or authorize the SIP session.

I would build this first with SIP.js + WebRTC + Asterisk PJSIP/WSS, rather than putting QUIC into the first production version. Your existing SIPml5 test proves that your Asterisk WebRTC infrastructure is already viable; the next step is turning that into a clean reusable phone component with the event API above. 
One newer Asterisk option is also worth keeping in mind: Asterisk's chan_websocket can provide application/media WebSocket connectivity and supports control events such as ANSWER and HANGUP, but it is aimed at application/external-media use and is not a replacement for the normal SIP-over-WSS WebRTC phone architecture.
